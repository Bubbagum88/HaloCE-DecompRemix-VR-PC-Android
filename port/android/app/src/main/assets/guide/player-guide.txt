# Halo CE Quest VR + Android 1.0.19-test38

Private test candidate, Android version code 49. The accepted public baseline
remains 1.0.18. This candidate is not a public release or headset acceptance.
The owner requested packaging the current work because of usage limits; the
remaining work and testing are recorded in TEST38-DELIVERY-STATUS.md.

## Installation

Install the Quest APK on the headset or the Android APK on the phone over the
matching existing app. Do not uninstall to update. Both use the existing signing
identity and remain separate apps. Keep a backup of saves/settings. Import your
own supported game data; no maps, ISOs or XISOs are included.

## Main changes

- All gun classes now have scope adjustment profiles, including SPNKR. These
  adjust authored zoom views; they do not add zoom to weapons that lack it.
- Vehicle/turret reticle previews no longer apply enemy target attraction.
  Normal handheld reticles and native projectile behavior are preserved.
- The supplied USA Original, Rev 1 and Rev 2 images contain identical 24-map
  sets and passed the production importer. This finding applies to those three
  images, not every regional, custom or corrupt image.
- Campaign compatibility extends to networks 15-24. An explicit optional legacy
  12-14 setting reproduces their old presentation behavior, with warnings about
  missing host allegiance updates. Hosting stays network 24; original-map PvP
  remains 11-24, and Custom Edition maps require 23/24.
- Optional physical reloads, object/NPC interaction, ragdolls, impact damage,
  contact refinements, virtual vehicle controls and parkour are described below.
  Existing Android touch/gamepad controls and Safe geometry defaults remain.

## Manual reload: off by default

Enable **MANUAL RELOAD** in VR Controls. This is a solo feature; online games
retain native reload. **SHOULDER POUCH** and **HIP POUCH** are separate toggles,
both on initially. Pouches follow the free-hand side automatically: left with
a right-hand gun, right with a left-hand gun.

Grip the magazine, pull it clear and release. Grip near an enabled pouch for a
replacement, align it with the weapon socket and release to seat it. A short
pulse confirms alignment; seating takes 0.10 seconds. Then finish as follows:

| Weapon | Reload finish |
| --- | --- |
| Assault rifle / sniper | Pull and release operating handle relative to gun |
| Pistol | Pull and release slide |
| Shotgun | Insert one shell, then pull/release pump; one round per cycle |
| SPNKR | Grip/release the push-bar latch after insertion |
| Flamethrower | Grip/release canister cover after insertion |
| Needler | Insert the authored crystal bundle; no invented bolt |

The normal reload button cancels the physical sequence and uses native reload.
Ammo transfers through native rules at completion. Battery weapons retain their
native battery/heat behavior. Unsupported custom/non-player reload rigs retain
native behavior. See MANUAL-RELOAD.md for exact profiles and cancellation rules.

## Hand contact and grabbing

**CONTACT VOLUMES** uses cached collision volume probes; OFF retains ray probes.
**CONTACT LOG** enables aggregate diagnostics. **CONTACT LIMIT** bounds visual
hand separation: an excessively obstructed arm/hand is hidden coherently and
restored as the controller returns, rather than moved through a wall. Detached
reload parts and held world/NPC surfaces participate in finger contact.

**WORLD GRAB** is off by default. With a free hand, press grip close to a valid
surface. Two hands can share an object or hold separate ones. Intentional
release throws; tracking loss or cancellation does not. Loose weapons/equipment
retain native physics. Eight audited loose scenery tags use collision-derived
bounding boxes and constrained movement; structural scenery is not made movable.
See VR-LOOSE-PROPS.md for the exact list and conservative-collision behavior.

**NPC GRAB** is off by default. Supported native Grunts, Jackals, Marines and
crew use one-hand handling. Elites, Hunters, Flood combat forms and carriers
require two distinct limb grips for lifting. Living NPCs and identifiable
corpses use articulated poses. Released bodies settle; living NPCs recover with
clearance checks and available native get-up animations. Dead bodies are never
revived. **ACTIVE RAGDOLLS** selects a bounded pool of 1-4.

**IMPACT DAMAGE**, **IMPACT SPEED** and **IMPACT CAP** control collision-based
physical damage. Only explicitly handled objects are tracked; authority remains
with the local game/co-op host. Native damage rules and normal falling damage
remain in place. Scripted/named, seated, invalid or unsupported entities are
protected rather than blindly converted into physics objects.

## Co-op physical interactions

The host must enable **VR INTERACTIONS** in Server Setup. New interaction
capabilities must negotiate successfully with the required peers. Enhanced physical interactions support at most four remote peers; above that limit they fall back to native behavior without reducing ordinary co-op capacity. Compatible
Quest clients send grip intent; Android or Quest hosts validate it and simulate
the objects. NPC poses, planted hand contacts and collision poses are synchronized.
No client may submit authoritative damage or arbitrary object transforms.

Competitive multiplayer and incompatible/mixed co-op sessions retain native
behavior for these custom interactions. Ordinary co-op and VR avatar rendering
remain separate features. Manual reload and parkour remain solo-only in this
candidate. Actual multi-device interaction testing is still required.

## Closer contact

**GRAB CONTACT** defaults to AUTO, following world/NPC grabbing. **BODY RADIUS**
defaults to 25 cm and offers 18-60 cm, never exceeding the native maximum.
ON enables it independently; OFF uses the previous CLOSE CONTACT policy.
This is solo-only. Expansion waits for free space; NPC hitboxes and solid world
collision are not removed.

## Virtual vehicle controls

Enable **PHYSICAL HANDLES** for first-person driving. Warthog, Ghost, Scorpion
and Banshee profiles have distinct virtual wheel/yoke appearances, native seated
anchors and per-vehicle reach, lateral, height and size adjustments. Grip near
a control, turn it to steer, then release for the normal selected steering mode.
Stick throttle remains; Banshee pitch retains its selected normal aim source.
**VIRTUAL WHEEL** controls visibility independently of grabbing.

Physical vehicle controls are off by default. The wheel is visible when that mode is enabled unless its separate visibility option is disabled. Third-person vehicles with right-hand steering
remain the default. Passengers/turrets keep their existing controls. First-person
vehicle comfort still needs refinement; third-person remains recommended.

## Parkour: off by default

**WALLRUN**, **WALLJUMP** and **GRIP CLIMB** are independent solo-only options.
Run/jump against a vertical wall to wallrun. A fresh jump input gives a
look-directed outward leap. Grip a static wall and pull to climb; release after
an arm pull to launch. Speed, duration and launch settings are adjustable.
Native capsule collision remains active. Moving objects, characters and vehicles
are not climbing anchors. Focus loss, menus, death, seats and state resets cancel
transient ownership.

## Testing and support

Start with ordinary gameplay and new features OFF. Then enable one subsystem
at a time. Headset comfort, real collision scenes, campaign recovery, performance,
checkpoints and live co-op require device testing; automated tests cannot prove
them. See TEST38-DEVICE-CHECKLIST.md and TEST38-DELIVERY-STATUS.md.

Report version, headset/OS, map/data set, solo/host/client role, settings, steps,
launch log and a short video. Never send disc images or signing keys.
DM **@MeWhenINameMyself** on Discord or report in the support server:
https://discord.gg/S9uSCKxKx

The baseline installation/control reference follows in the launcher's offline
guide. These candidate notes take precedence for the new features above.

# Halo CE Quest VR + Android player guide

This guide describes the unpublished **test37 candidate / 1.0.18-test37 / OpenCE Build 157 / network 24**. It is provided for testing, not as a public release. For the current public build see [v1.0.16 release notes](RELEASE-1.0.16.md).

## Install and update

Use the Android APK for a phone/tablet and the Quest APK for standalone VR. On Quest, enable Developer Mode and sideload with SideQuest or ADB. Install over the existing project app so imported game data, saves and settings remain. Do not uninstall or clear app data. Supply your own supported Xbox Halo CE game files; none are included.

Open the launcher’s **Game files & versions** to import an ISO/XISO or extracted game folder, inspect the recognized cache build and select an installed set. You can import multiple sets and switch between them without replacing the original. The **Versions & updates** page checks the project's compatible releases and provides official upstream downloads separately. Upstream files are not applied blindly to the integrated VR/network runtime.

## Browse, join and host in game

The OpenCE multiplayer flow is in the game menus. Create/select a profile if prompted.

| Goal | Menu path |
| --- | --- |
| Join a public PvP or campaign game | **Play → Multiplayer → Join Game → Server Browser**; refresh and choose a listing |
| Join a nearby LAN game | **Play → Multiplayer → Join Game → LAN** |
| Join from an invite | **Play → Multiplayer → Join Game → Direct Link** and paste/enter the invite |
| Host PvP | **Play → Multiplayer → Create Game → Internet or LAN → Multiplayer → map → game type → Server Setup** |
| Host campaign co-op | **Play → Multiplayer → Create Game → Internet or LAN → Singleplayer → mission → difficulty → Server Setup** |

In **Server Setup**, choose the server name, player limit, public/private listing and password as needed. PvP also has match rules; campaign has co-op options. Start the lobby, invite players or publish it, then start the match when ready. The campaign player selector offers limits up to 128; start with a small group because the maximum is not a performance guarantee.

The launcher also has **Browse multiplayer servers** and **Browse campaign co-op servers**. Refresh, then open **Network** to compare reported server/player populations, busiest first. Choose **All compatible networks** (11-24) or an exact version from 11 through 24. The default is 24. This sets the native client's discovery and join target on the next game launch as well as filtering the launcher list. The selection is shared across both browsers and game-data sets. Close the game before changing it; it cannot switch while a game is running.

Versions 11-22 are for original Xbox-map PvP only. Campaign co-op and Custom Edition require a version23 or version24 host. Hosting and signed listings from this app always use network24; choosing an older join target does not make a network24 host compatible with old clients. Versions below 11 and unknown future versions remain unavailable. This is backward client compatibility, not a replacement for every historical engine or compatibility with retail Halo PC/Custom Edition, MCC or retail Xbox networking.

Counts are catalog reports, may be stale, and do not include every private/LAN game. Up to four supported HTTPS catalogs can be configured; only the default community catalog has been independently verified in this pass. MQTT brokers are mirrors of discovery, not separate selectable game protocols. The native in-game browser continues to use signed MQTT and LAN discovery with the selected client target.

Compatible maps/resources and a reachable network route are still required. Public listings do not relay traffic. NAT, firewall/VPN, mobile-data restrictions, Wi-Fi isolation, passwords, full lobbies and missing or different game content can prevent joining. PvP directory joins can prompt for an installed map/game-data set; campaign joins do not automatically choose a matching revision. If joining fails, record logs from both host and client, host version, selected join target, map/revision and network type. Device cross-play testing is still required; no universal compatibility is claimed.

The launcher server directory is a fallback list; it does not replace in-game host setup, LAN discovery or signed MQTT discovery. Saved invites, game-data management, updates, controller/touch settings, guides and logs remain available.

## Controls

### Quest Touch

- Left stick moves; right stick turns and, when held down, crouches by default.
- Weapon-hand trigger fires; off-hand trigger zooms.
- Right A jumps/confirms; right B reloads/uses. Left Y switches weapons; left X throws a grenade, and holding X changes grenade type.
- Left stick click toggles the reticle (visible at startup); right stick click performs native melee; clicking both sticks recenters.
- Weapon-hand grip handles physical weapons; the off-hand grip locks to the support point when the two-hand option is enabled.
- Bring the off hand to the left side of the head to toggle the flashlight when its gesture is enabled. Adjust or disable the reach in **VR Settings → Head Gestures → Flashlight**.
- Hold the gun hand by its own temple to toggle the HUD when enabled. A cycles co-op spectate targets or votes in a skippable cutscene.
- Point at a menu row and press the trigger. Thumbstick/D-pad menu navigation is available as well. B returns/back. Left-handed mode mirrors supported actions.

To put crouch back on left-stick click, open **VR menu → Controls → Page 2 → L Stick Click → Crouch**. Reassign the reticle on **Buttons** if needed.

### Android gamepad

The default Xbox-style mapping is: left stick move, right stick aim, RT fire, LT grenade, A jump, B melee/cancel, X reload/use, Y switch weapon, LB flashlight, RB grenade type, stick clicks crouch/zoom, and Start pause. D-pad or left stick navigates menus; A confirms and B returns. Controller labels can vary; use **Controller & touch settings** for face-button swap, dead zones, response, trigger threshold and vibration.

### Android touch

Use **MOVE + swipe** to move and aim, or drag **FIRE** to move, aim and fire together. Tap **HUD** while playing to reposition or resize touch controls and adjust opacity, color and response. Gyro aiming is optional and off by default. Touch visibility can be **Auto**, **Always show** or **Always hide**; Auto restores touch when a connected controller disconnects.

## VR settings

Open the pause menu and choose **VR Settings**. Use Next Page and Back to move between settings pages. Arrow controls decrease/increase values; A/right advances or confirms. **Legs + Arms**, **Safe geometry**, **Third Person vehicles** and **Right Hand steering** are defaults. First-person vehicle view remains experimental. Changes save; restart after changing geometry compatibility.

Settings include body/hand modes, fingers, hand/gun calibration, weapon grip and support grip, controls, gestures, HUD/wrist HUD, scopes, vehicles/seats, comfort, graphics, display and controller tracking corrections. Optical finger tracking is not used; fingers follow controller sensors. See [controls and options](CONTROLS-AND-OPTIONS.md) for exact defaults and the full menu inventory.

## Revisions, logs and support

For the best compatibility, use the original Xbox Halo: Combat Evolved XISO. Rev 1 and Rev 2 images can be imported, but are not recommended; different revisions may contain different game or map files and can prevent players from matching. The launcher recognizes supported Xbox cache format/build identifiers, but cannot determine every disc label from a filename or promise full-disc integrity. The server browser cannot automatically prove which ISO revision a host uses. SPV1 is experimental and unverified; file sizes fitting the current reader limits do not establish protected-map/resource/campaign support.

Each launch writes a detailed log under **Download/HaloCE** when Android allows; app-private storage is used as fallback. For crashes, failed joins or desyncs, share logs from each peer and include device/model, OS, app/network version, game-data set, map/mission, network type and reproduction steps. Contact **@MeWhenINameMyself** or the [Halo CE Decomp Discord](https://discord.gg/S9uSCKxKx). Remove private invite/device details before sharing.
