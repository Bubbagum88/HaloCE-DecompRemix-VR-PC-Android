# Test46 requirement disposition

Test46 is focused on the supplied grab/contact report and the added request to
grab allies as well as enemies. It carries Test44 and earlier features forward.

| Requirement | Test46 implementation | Evidence and boundary |
|---|---|---|
| Actual contact followed by a fresh press | NPC/enemy/ally and prop acquisition use the tracked palm-volume overlap against the target's authored collision model. Climbing overlaps solid surface collision. Magazine/pouch and wheel interactions use their documented authored or virtual contact volume. A new Grip/configured-input edge is required; a ray cannot acquire. | Production-source harnesses and source guards cover local, host-validated co-op, world props, reload, climbing and handles. The Quest checklist still requires touch-first and press-first negative/positive cases. |
| Keep an NPC attached while Grip stays down | Ordinary hand displacement and hand-to-joint separation no longer clear the held state. The target follows through bounded per-step movement. A large tracking sample rebases throw velocity to zero. Invalid tracking, lost authority, stale owner/entity, unsafe target state and explicit Grip release remain logged exits. | `test_vr_npc_interaction.py` exercises the production target-follow helper and checks the former release thresholds are absent. Video/log evidence does not include a clear held-target release reason; a Quest retest is needed. |
| Keep held local/remote props attached | Local and remote props likewise remain owned through ordinary distance/strain. Remote target movement is rate-limited on the host; large samples cannot teleport the object or clear the grip. | Production release/remote host-oracle tests; the host collision stub is not the retail engine collision implementation. |
| Extend generic custom NPC rig coverage | The opt-in solo fallback admits the engine's generic `_actor_none` plus grounded custom `_actor_engineer` variants after race, non-swarm/non-flight, authored biped capsule, native graph, and head-under-pelvis/branch validation. The native actor enum is fixed, so this is bounded automatic graph reuse rather than arbitrary skeleton retargeting. | `custom_rig_graph_valid()` and `custom_humanoid_rig()` are extracted into `test_vr_npc_interaction.py`; fixture cases cover malformed parent/head topology, invalid capsule, biped/actor flight flags, and the grounded Engineer path. Real custom-tag and headset acceptance remain pending. |
| NPC rig slot limit vs native corpse limit | **NPC RIG SLOTS** configures this mod's active articulated interaction/settling/recovery pool from 1-8 (new-config default 8). It does not raise Halo's native corpse-ragdoll count. | `vr_npc_interaction.h` fixes the mod pool at 8; `free_state()` clamps to 1-8 and the VR menu exposes those values. Native corpse cleanup remains engine-owned. |
| Allow allies as well as enemies | Existing supported profiles include Grunts, Jackals, Marines, crew, Elites, Combat Forms, Hunters and Carrier Forms. A friendly living actor with a non-immediate command list may now be held; only transient control inputs are suppressed while its original team/orders/command data remain intact. Immediate forced orders, unsafe states and unsupported rigs stay blocked. | Production `eligible()` fixture covers friendly Marine and crew with ordinary orders, immediate-order rejection, enemy script rejection and preserved enemy-type coverage. Actual campaign actor behavior needs Quest verification. |
| Ragdoll-on-death and retention | Halo's native death-animation completion path calls `biped_start_limp_body_physics()` for eligible authored bipeds. The native tag flag, at-rest and airborne checks remain in force; the mod does not override them or force every species to ragdoll. A corpse already grabbed by the mod returns to native limp physics after settling. Normal engine cleanup remains authoritative. | Source review confirms the native completion handoff and native guards; supported species' actual tag flags and Quest deaths still need device confirmation. `NPC RIG SLOTS` is not a native corpse limit. |
| Automatic recovery of fallen mission actors | `vr.npc_rescue` is a separate opt-in, solo-only recovery for eligible live encounter actors after ten seconds unsupported/out of map; it restores a recorded grounded pose only when a full standing capsule is clear. | Production eligibility/timer/placement checks now use the real resumable-script field; an invalid field reference found in source audit was fixed and a guard added. This is not revival, general script rescue or guaranteed recovery of every actor/mission. |
| Whole-vehicle physical lifting | **Included in the Test46 source and candidate build.** **LIFT VEHICLES** follows contact-grabbed hand anchors in all three translation axes and tracked hand orientation; two hands add a second axis constraint. It uses bounded native vehicle linear/angular velocity so the engine continues to integrate position/orientation, gravity and collision. Deliberate Grip release retains only capped native linear/angular velocity; there is no teleport or added throw impulse. | Default-off, local-only; contact/grip still required. Supported only for unoccupied, non-destroyed, unparented, unnamed Warthog, Ghost, Scorpion and turret vehicles with validated native physics. Network, boats, aircraft, other types and named/movie-star vehicles stay stock. `test_vr_vehicle_lift.py` covers the bounded control math and source guards; Quest hand-feel, collision and release still need device testing. |
| Persistent discarded magazines | **Included in the Test46 source and candidate build.** Retain the existing local visual magazine props across same-map checkpoint, campaign-state and core restores in the running session. Before restore, clear saved owner datum exclusions so reused object indices cannot become stale collision ignores. New-map initialization/disposal, disabling the option and online-session gating still clear the props. | Focused C/source test covers owner rebasing and restore/map lifecycle policy. Pool remains capped at 32 with no eviction; when full, later debris visuals are skipped. Props are not save-file serialized, networked or ammo-bearing. Quest persistence/performance still needs device confirmation. |
| Selected Build167 voice chat | Host-relayed Opus voice uses optional network messages 80-82 without changing network24. Android declares `RECORD_AUDIO` and requests it asynchronously only when transmit is enabled/allowed and PTT/Open Mic is active. VR offers Off/PTT/Open Mic, receive volume 0-200% (0 mutes all), and a controller PTT binding defaulting to None. Flat Android supports keyboard PTT (V by default) or Open Mic, with no touch/gamepad PTT binding. Hosts configure routing/lobby/bitrate/proximity in Server Setup. | `test_voice_chat_integration.py` checks source/config/build wiring, separate permission/device failure statuses, async permission bridge, 10-second transient-device retry, routing IDs, PTT/defaults and menus; `test_test31_menu_assets.py` checks embedded host rows/options/pointer input. Per-player mute UI is absent. Permission prompt, capture/playback, Android routing, older-peer interoperability and two-client lobby/match behavior still require device testing. |
| Campaign capacity and enhanced co-op boundary | Campaign player-count options remain OpenCE's. A 128-machine transport table does not establish a stable 128-player campaign. Enhanced world-object interactions negotiate above four remote peers when the host enables them and every peer supports the capability; articulated NPC palette synchronization remains capped at four remote peers. Manual reload and parkour remain solo-only. | The candidate does not change ordinary campaign capacity. Existing compatibility/capability tests cover protocol guards, not high-count campaign stress or headset acceptance. Above the NPC-palette cap, physical NPC behavior falls back to native behavior. |
| Manual reload retained | Supported authored weapon profiles use contact, a newly pressed selected Grip/Trigger input, body-side hip/shoulder pouch pickup, socket-aligned magazine/shell insertion, weapon-relative charging and the native ammo commit. Left-handed side selection, cancellation and native animation handoff remain. Supported solo profiles suppress native automatic reload while Manual Reload is enabled; the normal reload button cancels a physical transaction without committing ammo. | See `MANUAL-RELOAD.md`; seven authored profiles, ammo conservation, input ownership and cancellation have production tests. Unsupported/custom profiles retain native behavior. Reload is solo-only and device checks still need Quest action tests. |
| Parkour and grip climbing retained | Separate off-by-default, solo-only Wallrun, Walljump and Grip Climb controls. Wallrun uses wall probes and bounded native velocity; Walljump needs a fresh jump edge; Climb needs contact with a valid solid vertical surface and moves the body through native collision. | See `VR-PARKOUR.md`; production module tests cover enabled/disabled/network isolation, contact anchors, fresh edges, release, cooldown, ownership and bounds. Campaign geometry/comfort and Quest movement still need device acceptance. |
| Sprint and melee intent retained | Arm Run and optional Left Stick Click Button Sprint share bounded Sprint Speed; Arm Run Sensitivity is separate. Optional FIST REQUIRED distinguishes closed-fist melee from open-hand grabbing. | Source math/control tests and menu/config wiring are in the cumulative runner. Solo movement behavior, physical intent and binding restore need Quest checks. |
| Hands, holsters and haptics retained | Continuous per-finger surface/held-component contact and bounded hand compliance remain. Four holster slots remember exact weapon datums and mirrored body positions; empty-hand transitions clear weapon-held state. One master HAPTICS setting scales interaction effects, with the separately requested HOLSTER HAPTICS mute for holster-only buzz. | Contact, holster, finger, input lifecycle and haptic fixtures are registered. Hand-mesh stability, holster retrieval, reticle/zoom disappearance and haptic comfort need device checks. |
| Custom scenery bounds | The optional scenery feature uses a conservative exact audited tag allowlist; custom NPC graph handling is a separate setting and path. | Arbitrary BSP scenery and script-owned scenery are refused. Custom NPC graph fallback is limited to validated generic/Engineer humanoid variants; arbitrary skeleton retargeting is unsupported. |
| Keep existing interactions and platforms stable | Vehicle lifting stays behind its existing OFF-by-default toggle. The voice permission bridge does not prompt at game startup. No network version, Android touch/gamepad, Safe Geometry default, launcher, saves, weapon aim, reload state machine, manual reload, parkour state machine, holster, or rendering defaults are intentionally changed. | Focused voice/vehicle tests and the cumulative regression runner pass; both flavor builds and package gates are still required. Device acceptance is pending. |

## Existing scope recorded, not expanded in Test46

The candidate also carries forward Test44's Safe Geometry VR default, existing
Android touch layout/editor and preset import/export, controller behavior,
managed game-data/revision selection, launcher network selector and in-game
browser, A10 crosshair-ray calibration, scopes, vehicle/turret controls, co-op,
logging and update UI. The cumulative runner covers their source regressions;
this pass does not claim new device acceptance for those baseline systems.

## Acceptance boundary

Source and host-oracle tests do not substitute for physical Quest testing. See
`TEST46-DEVICE-CHECKLIST.md`; retain the exact APK hashes and source revision in
the final delivery record. The public release remains unchanged.
