### 8 Steam Frame — full research in `D:\HaloQuest\_scratch\t72\frame\FRAME-NOTES.md` (read it)
Sources: Valve's Steamworks Frame docs (input, adb_lepton, loadgames, engines/*, debugging, compat,
perf_criteria, vrpreferences); **Lepton's source** cloned at `_scratch/t72/frame/dl2/lepton` (v3.0.7);
ringfall-mjolnir-vr (CC0, field-tested on the Frame) at `_scratch/t72/frame/dl3/ringfall` (Frame use only).
Why both APKs fail today, verified in Lepton's code:
1. Lepton starts the first MAIN+LAUNCHER activity (our 2D `LauncherActivity`) and, for Steam/devkit launches,
   runs **headless**: the 2D window is hidden unless a `lepton-show-flatscreen` file is in the title's folder.
   VR APK: the launcher waits invisibly. Flat APK: the whole game is invisible.
2. `LeptonProcessObserver` ends the container when the process named exactly the package dies: our VR game runs
   in `:halo_game`, so a trimmed launcher process kills the game, and quitting the game leaves the container up.
3. The Frame may list the implicit OpenXR layer `XR_APILAYER_VALVE_fdm_injection`
   (`libVkLayer_VALVE_fdm_injection.so`), which an Android app cannot load: the Khronos loader then fails
   `xrCreateInstance`. Ship a pass-through stub under that name (ringfall `port/android/xr_layer/
   fdm_injection_stub.c`, built 16 KiB aligned in its `android_build.py`).
4. Lepton reinstalls the APK and **empties `/sdcard/Android/data` on every start**; `/sdcard/Documents` is the
   SteamOS user's `~/Documents` but Android 11 scoped storage blocks it: use `/home/<user>/Documents/<folder>`
   directly (bind-mounted; user from property `waydroid.host.user`, Frame: `steamos`). Data, config, saves, logs
   must live there. Pick a folder name not `HaloCE` (ringfall's installer renames `~/Documents/HaloCE`).
   Note our existing `tools/steam_frame/deploy.sh` + `extract_maps.py` (adb/SSH deploy to Documents/HaloCE) and
   `docs/VR_ARCHITECTURE.md`'s devkit title "HaloCEVR": update them to the new path.
5. Valve's Mesa in Lepton writes kernel trace markers hundreds of times a frame (50 vs 72 fps): after GL context
   creation and after the XR session, point fds whose `readlink` contains `tracing/trace_marker` at /dev/null
   (ringfall `host_gl_quiet_trace_markers`, after astromaddie/HaloCE-VR).
Already fine in ours: OpenXR 1.0; only listed extensions enabled; refresh-rate refusal non-fatal (SteamVR in
Lepton offers only the current rate or none); LOCAL/VIEW spaces; SRGB8_ALPHA8/RGBA8; no multiview needed; HUD
quad alpha = max(rgb) already (SteamVR draws quads by alpha); Frame bindings match Valve's official paths;
clipboard guarded (SDL patch); .so LOAD align 0x4000; native API 28 (Lepton is SDK 30, also an Android 14 image);
4 KiB kernel pages (FEX); no `/dev/input` in Lepton (no doubled gamepad).
**Plan (all to do):** Lepton detection (props `lepton.app_id` / `lepton.headless` / `waydroid.host.user`,
Build.MANUFACTURER "Lepton"; native `__system_property_get`); a main-process game activity for Lepton (keep
